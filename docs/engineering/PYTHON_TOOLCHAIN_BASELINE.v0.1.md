# HullQ — Python Toolchain Baseline v0.1

**Status:** ACCEPTED  
**Decision:** OQ-010 / ADR-0009

## Normative baseline

- Runtime: CPython `>=3.14,<3.15`
- Python version provisioning: uv-managed, `.python-version = 3.14`
- Project/dependency manager: uv; CI/bootstrap baseline pins uv `0.12.5` and permits controlled updates within the accepted 0.12 line
- Dependency lock: committed `uv.lock`
- Build backend: `uv_build`
- Python package layout: `src/`
- Formatter/linter: Ruff
- Blocking type checker: mypy strict
- Test runner: pytest
- Coverage: coverage.py with branch coverage; global minimum 90%
- Property-based testing: Hypothesis where invariants benefit
- JSON Schema validator: `jsonschema`, Draft 2020-12 selected from `$schema`
- HTTP client: HTTPX with explicit bounded timeouts/concurrency
- Concurrency: stdlib asyncio + `TaskGroup`
- Stage-2 local state: stdlib SQLite; explicit transaction policy; no ORM initially
- Dependency vulnerability signal: pip-audit in CI/release workflow

## Dependency policy

The repository MUST distinguish:

- runtime dependencies under `[project].dependencies`;
- development/test/tool dependencies under standardized `[dependency-groups]`;
- exact resolved versions in `uv.lock`.

Stable releases are preferred. Preview/prerelease features MUST NOT become blocking tooling without explicit approval.

## Configuration policy

Python tooling SHOULD be configured in root `pyproject.toml` where the tool supports it. Avoid proliferating config files unless a tool lacks pyproject support or separation materially improves clarity.

## Initial package shape

This is one package. Do not create a workspace or deployable service split until evidence requires it.

## Required gates

A Python change is not mergeable if any applicable gate fails:

1. lock consistency;
2. schema/fixture contract validation;
3. Ruff format check;
4. Ruff lint;
5. mypy strict;
6. pytest;
7. coverage floor;
8. relevant golden/property/regression tests.

Dependency vulnerability auditing is additionally required in CI/release flows that have network access.

## Change rule

A future switch from uv/Ruff/mypy/pytest or a Python-major runtime change is a tooling architecture decision and MUST update ADR/toolchain docs, CI and lockfile atomically.

## Repository bootstrap realization

The accepted baseline is realized by the root `pyproject.toml`, `.python-version`, `.github/workflows/ci.yml`, `.github/dependabot.yml`, `src/hullq/`, `tests/`, and first-party repository validation script.

`uv.lock` is mandatory but MUST be generated by uv against real package metadata; it is intentionally not hand-authored. Until a committed lockfile exists and locked Linux + Windows CI passes, the repository bootstrap remains incomplete even though OQ-010 itself is DECIDED.
