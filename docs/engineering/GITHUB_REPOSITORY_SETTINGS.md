# HullQ — GitHub Repository Settings Baseline

**Status:** REQUIRED WHEN THE REPOSITORY IS HOSTED ON GITHUB

These are repository-host settings and therefore cannot be guaranteed by files in a ZIP alone. They MUST be applied when the HullQ Git repository is created/hosted.

## Default branch

- default branch: `main`;
- force pushes to `main`: blocked;
- branch deletion for `main`: blocked.

## Ruleset

Prefer a GitHub repository ruleset targeting `main` rather than relying on overlapping legacy branch-protection rules.

Required rules:

- changes land through pull requests once normal development begins;
- required status checks must pass before merge;
- require branch to be up to date before merge once CI stability is established;
- require the CI checks generated by `.github/workflows/ci.yml`;
- block force pushes;
- do not create broad bypass rules for coding agents or automation.

For a solo-development phase, mandatory human approval count MAY remain zero; CI and docs-to-code gates still apply. If additional maintainers join, review requirements SHOULD be revisited.

## Security / dependency settings

Enable where available:

- dependency graph;
- Dependabot alerts;
- Dependabot security updates;
- Dependabot version updates using `.github/dependabot.yml`;
- secret scanning / push protection when supported by the repository plan.

## Merge policy

Prefer squash merge for ordinary feature/documentation pull requests so the default branch remains readable and compatible with Conventional Commit-style final messages. Rebase merge MAY be used deliberately; merge commits SHOULD be disabled unless a future workflow specifically benefits from them.

## Required-check naming

Do not hard-code required check names in the ruleset until the workflow has run at least once in the hosted repository. GitHub requires recent successful checks to select/validate expected sources reliably.
