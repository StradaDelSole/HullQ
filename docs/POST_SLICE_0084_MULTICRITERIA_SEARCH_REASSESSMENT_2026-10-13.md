## What is selected

One coherent end-user capability: a **reusable, explicitly typed supported-criterion registry and shared multi-criterion evaluation/serialization/UI path** for existing public native Buyer Search and the accepted private broker DRAFT Search-fit preview, initially delivering:

- **LOA (length overall) numeric hard filter:** minimum, maximum or inclusive min/max range; one criterion/dimension, not three artificial ordinal criteria. Exact positive SI-metre Decimal input; baseline / NamedVariant `dimensions.loa_m`, qualified FieldResolution and independent publisher's actual `physical_boat.loa_length` claim. Supports all combinations with accepted `draft_max` and `keel_configuration`.
- **Rudder/skeg category coverage:** a bounded additional public `rudder_configuration` hard criterion, only for accepted `PhysicalBoat.rudder_configuration` enum values that can be safely projected from the actual `BoatDesign` schema generation. Legacy v0.5 `configuration.rudder_type` and structured v0.6 `appendages.rudder_position`, `rudder_support` and `rudder_count` require **generation-aware bounded mapping** and independent FieldResolution of every contributing dimension. A single v0.6 descriptor (such as `rudder_support=free`) does NOT generally prove `SPADE` or any other unique compound label; `rudder_balance` is independent and must not be inferred. Existing v0.1 PhysicalBoat claim vocabulary is a single coarse enum, not a replacement for the separate v0.6 rudder facts. Explicit conflict/insufficient applicability => UNKNOWN, never positive.
- **Long/full keel:** assess a conservative, *separately named amendment of the accepted second criterion* `keel_configuration` for `LONG_KEEL`, using explicitly documented design generation/pointer and exact mapping of an unambiguous `keel_type=full` with qualified evidence and an independently asserted concrete `LONG_KEEL` claim. Do not silently map `modified_full`, `long_fin`, `shoal`, `bilge`, etc. to `LONG_KEEL`. If the exact full→LONG_KEEL equivalence or variant/claim qualification cannot pass independent normative and E2E review, record its explicit blocker and keep the accepted v0.1 exclusion instead of fabricating acceptance.
- **One coherent browser experience:** public multilingual Buyer Search supports sparse combinations and preserves canonical URLs; the broker Search-fit preview supports exactly the newly admitted same filters on its authorized existing single-DRAFT target (illustrative scenarios only). Existing buyer requirement sensitivity for the old supported paths MUST NOT silently ignore an active new criterion; either preserve all active constraints correctly using the shared evaluator or visibly reject the unsupported sensitivity request without a false factual delta.

**Important:** This selection is a bounded *bundle* and future-scale foundation, not authority to expose arbitrary fields by schema introspection, silently admit a value from a database column or overhaul all Search features. A true public Search criterion counts only after implementation/independent Owner-accepted closure, not because this decision anticipates it.

## Decision / implementation reconciliation

**DECIDED_AND_IMPLEMENTED:** Two accepted public native technical hard criteria (`draft_max`, `keel_configuration`) and typed `TRUE/FALSE/UNKNOWN`/MUST-AND kernel; shared `FieldProjectionSpec` FieldResolution/configuration bridge; exact numeric Decimal; current-public eligibility; seller's independent concrete claims and cross-Organization conflict qualification; typed design/PhysicalBoat evidence; public canonical-URL and Astro/FastAPI surfaces; old pure-draft compatibility; private read-only Organization/PUBLISHER/MFA/DRAFT Search-fit from accepted SLICE-0084. Existing schemas contain `dimensions.loa_m` in v0.5/v0.6; `PhysicalBoat.loa_length` is persisted/edited. The PhysicalBoat rudder/keel enums and v0.5/v0.6 rudder structures exist, but are not already public searchable as rudder.

**DECIDED_NOT_YET_IMPLEMENTED:** LOA min/max/range public and broker filters; any `rudder_configuration` public hard criterion; current public `LONG_KEEL` admission; the bounded reusable registry and end-to-end multi-criterion UI contract; later beam, displacement, rig, hull material, ballast and derived metrics.

**EXPLICITLY_DEFERRED:** automatic schema/DB field-to-search activation; extra Search dimensions not demonstrably backed by both qualified canonical design/variant and concrete PhysicalBoat fields; migration to decomposed independent PhysicalBoat rudder position/support/balance claims; unreviewed v0.5-to-v0.6 equivalence, arbitrary property resolver, hidden scores/ranking, loosening publication/current eligibility, changes to paid organic Search neutrality, production data/pilot/launch; unbounded criterion import and all remaining Search breadth in 0085.

**GENUINELY OPEN, MUST BE RESOLVED BY READINESS/INDEPENDENT REVIEW BEFORE START:** exact guarded rudder configuration value/mapping table (generation-specific; may support only a strict subset with explicit unknown treatment); the normative adequacy of `full` as `LONG_KEEL`, and how to expose reduced coverage truthfully; precise allowed LOA lexical envelope and canonical min/max URL keys; browser sensitivity dependency impact; bounded typed registry design avoiding duplicative code and changing the legacy draft-only path. Any taxonomy decision that cannot be justified using existing accepted contracts and concrete code evidence is *not* silently delegated to the implementation agent. Require an explicit Owner decision for newly material semantics when needed.

**CONFLICT_OR_REGRESSION:** No accepted production regression observed during this reconciliation. The overlapping meanings of v0.6 position/support vs the flat existing PhysicalBoat rudder enum are a **known representation limitation** requiring explicit narrow mapping, not permission to conflate them. Historical `docs/POST_SLICE_0083_SEARCH_PRIORITY_REASSESSMENT_2026-10-13.md` is correctly historical; this Owner's new bundling decision supersedes only its implied one-criterion-at-a-time execution cadence.
