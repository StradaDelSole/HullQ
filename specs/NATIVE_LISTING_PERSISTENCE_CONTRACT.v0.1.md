# HullQ Native Listing Persistence Contract v0.1

**Status:** ACCEPTED
**Decision:** `docs/ARCHITECTURE_REBASELINE_2026-09-02.md`, codified for implementation by SLICE-0043
**Supersedes:** none (new contract)
**Normative language:** BCP 14 semantics apply to uppercase MUST/SHOULD/MAY.

## 1. Purpose

This specification defines the durable persistence boundary that composes:

- the SLICE-0040 `MARKET_IDENTITY_CONTRACT.v0.1` `NativeListing` identity, and
- the SLICE-0041 `MARKETPLACE_PUBLISHING_ELIGIBILITY_CONTRACT.v0.1` authorization decision

into one authorized, durable, idempotent PostgreSQL creation of a
`NativeListing` creation envelope.

Durable creation is **not** public publication. It defines representation
and authorized persistence of the smallest immutable creation envelope
only. It does not define listing lifecycle/status, freshness/
reconfirmation, the complete yacht/listing field catalog, public pages,
media, leads, pricing, FastAPI/UI, or Account/Organization/Membership
persistence. Those remain governed separately.

## 2. Persisted envelope

A durable `NativeListing` creation envelope holds exactly:

```text
NativeListingId               (SLICE-0040 identity, sole primary key)
publishing_organization_id    (MarketplaceOrganizationId value)
created_by_account_id         (AccountId value)
market_episode_id             (MarketEpisodeId value | NULL)
broker_listing_reference      (str | NULL)
content_hash                  (internal persistence evidence, not a listing field)
created_at                    (database-generated TIMESTAMPTZ)
```

No other field is persisted by this contract. Adding price, currency,
location, title/description, technical/equipment/refit/tax/registration or
any other listing-fact field requires a separate accepted PhysicalBoat +
Listing Field Contract.

### 2.1 NativeListingId

MUST be the accepted runtime-distinct `NativeListingId` from
`MARKET_IDENTITY_CONTRACT.v0.1`. MUST NOT be minted from broker reference,
Organization ID, MarketEpisodeId, or any other visible data. Is the sole
primary key of the persisted row.

### 2.2 publishing_organization_id

MUST be derived from the exact `candidate_organization.id` evaluated by the
SLICE-0041 eligibility decision for this creation attempt. MUST NOT be
independently read from a separately supplied request/payload field. No
database foreign key to an Organization table is declared: no durable
marketplace-Organization table exists yet, and this contract MUST NOT claim
referential integrity it cannot truthfully enforce.

### 2.3 created_by_account_id

MUST be derived from the exact `account_id` evaluated by the SLICE-0041
eligibility decision for this creation attempt. MUST NOT be independently
read from a separately supplied request/payload field. No database foreign
key to an Account table is declared, for the same reason as §2.2. This
field is immutable creation provenance only, not a general ownership/
current-editor model.

### 2.4 market_episode_id

Optional. `NULL` represents a durable MarketEpisode-unresolved appearance;
an explicit value represents a durable explicitly linked appearance. No
database foreign key to a MarketEpisode table is declared, for the same
reason as §2.2. Persisting an explicitly supplied typed link is NOT
permission to infer, resolve, deduplicate or validate physical-vessel
identity — no HIN/CIN/name/year/location heuristic is introduced by this
contract.

### 2.5 broker_listing_reference

Optional broker/dealer-side inventory/reference token.

- `NULL` is allowed.
- When supplied, it MUST contain at least one non-whitespace character; an
  empty or whitespace-only value is rejected before any database write.
- The supplied token MUST be preserved exactly as given; no normalization
  (case-folding, trimming, canonicalization) is invented by this contract.
- It is NOT a HullQ identity: it MUST NOT mint a `NativeListingId`, MUST NOT
  trigger MarketEpisode resolution or physical-vessel deduplication, and
  carries no global-uniqueness requirement.
- No broker identity or professional status may be inferred from its
  format.

### 2.6 content_hash

An internal deterministic semantic fingerprint of the immutable envelope
(publishing Organization, creator Account, MarketEpisode link, broker
reference — excluding the `NativeListingId` itself, which is the row's own
stable identity). Used only for idempotency/collision detection. It is
persistence evidence, never a broker-facing listing field, never returned
as part of the typed readback.

### 2.7 created_at

Generated by the durable persistence/database boundary at first creation.
Stored as a timezone-aware PostgreSQL timestamp. MUST NOT be accepted as
trusted client input. MUST remain unchanged across an idempotent retry. Is
metadata about HullQ creation time only — not evidence of listing
freshness, publication time, sale start time, or MarketEpisode start time.

## 3. Authorization gate

Creation MUST evaluate the real accepted
`evaluate_native_listing_publishing_eligibility(account_id,
candidate_organization, membership)` from `MARKETPLACE_PUBLISHING_
ELIGIBILITY_CONTRACT.v0.1` before any `NativeListing` database write.

```text
PublishingEligibilityDecision == ALLOWED  -> persistence may proceed
PublishingEligibilityDecision == DENIED(reason) -> zero NativeListing rows written
```

A caller-supplied boolean (e.g. `authorized=True`) MUST NOT substitute for
the real evaluator call. Every deterministic SLICE-0041 denial reason
(`NO_MEMBERSHIP`, `ACCOUNT_MISMATCH`, `ORGANIZATION_MISMATCH`,
`MEMBERSHIP_INACTIVE`, `PUBLISHER_ROLE_REQUIRED`, `ORGANIZATION_INELIGIBLE`,
`ORGANIZATION_UNVERIFIED`) remains meaningful and is exposed on a `DENIED`
creation result.

An `ALLOWED` decision documents domain eligibility only. It does not assert
that MFA, authentication, or actual publication has occurred; those remain
governed separately and are not weakened by this contract.

## 4. Creation result

The creation boundary MUST return an inspectable, mechanically distinct
result rather than `True`/`False`:

```text
CREATED         # new row persisted
ALREADY_EXISTS  # identical idempotent retry; original row unchanged
DENIED          # carries the underlying SLICE-0041 denial reason
CONFLICT        # same NativeListingId, different immutable envelope
```

`DENIED` MUST carry the underlying deterministic denial reason. `CONFLICT`
MUST NOT be mislabeled as authorization denial and MUST NOT carry a denial
reason. No probability/trust score is defined. No lifecycle/visibility
status is encoded in this result.

## 5. Idempotency and conflict semantics

```text
same NativeListingId + same immutable semantic envelope
  -> ALREADY_EXISTS-equivalent; exactly one row; original created_at preserved

same NativeListingId + different immutable semantic envelope
  -> CONFLICT-equivalent; fail closed; existing row unchanged
```

A conflicting envelope includes a change to any immutable persisted
semantic value: publishing Organization principal, creator Account,
optional MarketEpisode link, or optional broker listing reference.
Persistence MUST NOT implement UPDATE/UPSERT-overwrite behavior to make a
retry or a reused identity convenient.

Persistence MUST be race-safe. The accepted pattern is atomic insert/
conflict detection (`INSERT ... ON CONFLICT DO NOTHING` followed by an
exact content-hash/readback comparison) rather than a check-then-insert
race.

## 6. Exact typed readback

Readback by `NativeListingId` MUST reconstruct values that preserve the
accepted runtime-distinct identity kinds:

```text
NativeListing(id=NativeListingId(...), market_episode_id=MarketEpisodeId(...) | None)
publishing Organization = MarketplaceOrganizationId(...)
created by               = AccountId(...)
broker_listing_reference = str | None
created_at                = durable timestamp
```

A missing `NativeListing` MUST return `None`/not-found-equivalent without
inventing a record. Readback MUST NOT join to a nonexistent actor/
MarketEpisode table or synthesize BoatDesign/PhysicalBoat facts.

## 7. Transaction boundary

- Authorization is evaluated before any `NativeListing` write; a `DENIED`
  decision never opens a persistence transaction.
- A successful new creation commits exactly one durable row.
- An identical retry produces no duplicate row.
- A conflict leaves the existing row unchanged.
- A persistence exception does not leave a partial `NativeListing` row.

## 8. Schema authority

All schema for the table(s) covered by this contract MUST be introduced
through an Alembic revision descending from the accepted SLICE-0042
baseline (`6f1c2a9d0001`), per `docs/slices/SLICE-0042-acceptance-closure.md`.
No `003_*.sql` or later legacy SQL migration may be added; legacy
`001_initial_schema.sql` / `002_canonical_identity_schema.sql` remain
unchanged. No SQLAlchemy ORM domain model or generic repository/Unit-of-
Work architecture is introduced by this contract.

## 9. Non-goals

This contract explicitly excludes, and no implementation under it may add:

- listing lifecycle/status (`DRAFT`, `ACTIVE`, `PUBLISHED`, `WITHDRAWN`,
  `SOLD`, `ARCHIVED`) or any freshness/reconfirmation state;
- public listing pages/URLs, FastAPI endpoints, Astro/React UI;
- the complete yacht/listing/PhysicalBoat field catalog (price, currency,
  location, title/description, technical/equipment/refit/tax/registration/
  HIN/CIN, media/documents);
- Account, MarketplaceOrganization or OrganizationMembership persistence,
  or a foreign key to any such nonexistent table;
- physical-vessel identity resolution/dedup or MarketEpisode continuity
  inference;
- leads/`ContactRequest`, `BrokerageRequest`/referral, Saved Search/
  monitoring/alerts, pricing/entitlements, transaction/escrow/closing;
- Auth0/AuthIdentity/MFA/session/step-up authentication implementation.
